# Start here: working together on GitHub

GitHub keeps project files, their saved history, and discussions about proposed changes together. It helps us review AI-assisted work, share improvements, and keep projects usable when someone is away. It does not automatically run an app, back up its live database, or make AI-generated work correct.

**You do not need to learn programming to read documents, ask questions, or review a proposal.** Choose the task you want to do below; you do not need to read every guide.

## First visit

1. Sign in with the individual GitHub account you use for company work. Do not share an account or password.
2. Accept your organization invitation. If you do not have one, contact the person coordinating your onboarding through an existing company channel.
3. Open [the organization's repositories](https://github.com/Leuco-Tool-US?tab=repositories). As a member you can read every repository in the organization, including the private ones. If a repository is missing or shows a 404, check that you accepted your invitation and are signed in with your company account before assuming the link is wrong.
4. Open [the team directory](https://github.com/Leuco-Tool-US/leuco-vault/blob/main/docs/TEAM-START-HERE.md) to find the right repository. It is in the private knowledge vault, so sign in and accept your invitation first.
5. Read your project's README for its purpose, owner, and instructions. Do not install developer tools just to read or review a document.

## The terms, in plain language

| Term | Meaning |
| --- | --- |
| Repository, or repo | A project's files and their history. |
| `main` | The shared primary version of those files. It may still contain drafts. |
| Branch | A separate line of changes in the same project, so your unfinished edits do not change `main`. |
| Commit | A saved revision in Git, with a description of what changed. |
| Clone | Download a working copy together with its Git history. |
| Push | Upload local commits to the corresponding branch on GitHub. |
| Pull | Bring changes from GitHub into your local branch. |
| Pull request, or PR | A proposal to merge changes from one branch into another, with a review discussion. |
| Merge | Combine the reviewed changes into the destination branch. |
| Issue | A tracked question, problem, or task; it does not itself edit files. |
| Project board | A view that organizes issues and PRs; their detailed discussion stays in the linked item. |
| Actions/checks | Automated tasks, such as checking names or running tests. A green check only confirms what that task actually checked. |

Saving a file, committing, pushing, merging, and deploying are different actions. Some tools combine them into one button; read its label. Existing applications may deploy automatically after a push or merge, so read the project's release instructions before publishing changes.

## Working with Claude

Use approved company tools and accounts. Claude may help write, explain, and check changes, but its available actions depend on the environment and access it has. Browser chat, Cowork and Claude Code are not interchangeable.

Company workflow automation is being piloted; do not assume it is installed or that it creates branches and PRs automatically. These guides remain usable without a special prompt. The project should still show a real branch, actual changed files, check results, and a PR link. Human review includes trying the affected business task and questioning unexpected behavior.

## When you get stuck

For access, credentials, or sensitive material, contact your organization administrator privately. For an ordinary project question, open its **Issues** tab, search first, then select **New issue** and describe what you expected and what happened. Remove sensitive details from screenshots and error messages. If Issues is unavailable, contact the project maintainer through the existing company channel.

This guide is public. Keep internal procedures, business records, and private support details in the appropriate approved private location.
